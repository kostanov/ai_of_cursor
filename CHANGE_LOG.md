# CHANGE LOG

## 2026-06-02

### Аудит, дебаг и рефакторинг `utils.py`

- Закрыты уязвимости SQL-инъекций в `add_user` и `get_user_by_name` через параметризованные запросы.
- Исправлено управление ресурсами: операции с SQLite и файлами переведены на контекстные менеджеры `with`.
- Исправлен контракт `add_user`: функция теперь возвращает `int`, добавлена валидация входных данных.
- Убрана проблема мутируемого аргумента по умолчанию: `tags=[]` заменено на `tags: list[str] | None = None`.
- Небезопасное хранение паролей заменено на PBKDF2 (`sha256`) с солью и количеством итераций.
- Устранена гонка потоков в `set_active`: добавлен `threading.Lock`, хранится не более 5 последних активных пользователей.
- Улучшена устойчивость `get_user_by_name`: корректный возврат `None` при отсутствии записи и безопасный разбор `tags` из JSON.
- Проведена чистка и типизация кода: добавлены константы путей/настроек и вспомогательная функция `_ensure_users_table`.
- Проверки пройдены: `uv run ruff check utils.py` и `uv run ruff format utils.py`.

### Второй раунд аудита, дебага и рефакторинга `utils.py`

- Исправлены дефекты целостности модуля: устранены обращения к несуществующим именам (`_active_users`, `PASSWORDSPATH`) и недостающим типам (`List`, `Optional`, `Dict`).
- Восстановлена рабочая инициализация БД: добавлена функция `init_db()`, используемая в `self_test`.

- Стабилизирована работа со списком активных пользователей: `get_active_users_snapshot()` возвращает потокобезопасный снимок из `active_users`.
- Повышена читаемость и поддерживаемость: добавлены краткие docstring к основным функциям и уточнена сигнатура worker-функции в потоковой задаче.
- Повторные проверки пройдены: `uv run ruff check utils.py` и `uv run ruff format utils.py`.

### Аудит, дебаг и рефакторинг `api.py`

- Полностью исправлен синтаксис и структура модуля: удалены невалидные конструкции, восстановлен рабочий Flask-приложение файл.
- Убраны небезопасные паттерны доступа к БД: отказ от глобального соединения/курсора в пользу `get_connection()` и локальных контекстных менеджеров.
- Закрыты SQL-инъекции: вставка и выборка пользователей переведены на параметризованные запросы.
- Нормализованы маршруты и контракты API: `POST /users` (создание пользователя) и `GET /users/<int:user_id>` (получение пользователя).
- Добавлена валидация входных данных и корректные HTTP-статусы: `400` для некорректного `name`, `404` при отсутствии пользователя, `201` при создании, `200` при успешном чтении.
- Добавлена инициализация БД через `init_db()` с `CREATE TABLE IF NOT EXISTS users`.
- Для запуска API добавлен стандартный entry point: `if __name__ == "__main__": app.run(debug=True)`.
- Подключена runtime-зависимость проекта: `uv add flask`.
- Проверки пройдены: `uv run ruff check api.py` и `uv run ruff format api.py`.

### Второй раунд аудита, дебага и рефакторинга `api.py`

- Восстановлена целостность импортов и типов: добавлены недостающие `g`, `Any`, `threading`, `time`, а также заменены `List[...]` на `list[...]`.
- Исправлен lifecycle приложения Flask: удален хрупкий `@app.before_first_request`, инициализация БД выполняется через явный `init_db()` при старте модуля.
- Стабилизирован контекст БД на запрос: сохранена модель `get_db()` + `teardown_appcontext` для безопасного закрытия соединений.
- Нормализованы HTTP-ответы через `HTTPStatus` вместо магических чисел (`400`, `404`, `200`, `201`, `202`, `500`) для единообразия API-контрактов.
- Уточнена сигнатура `close_db` (`_exc`) для корректного прохождения линтера без изменения поведения.
- Подтверждена работоспособность после правок: `uv run ruff check api.py` и `uv run ruff format api.py` выполнены успешно.
